
Lekha - Implementation Plan
Oct 16, 2026 · @Eshaan Adyanthaya
The complete implementation plan - architecture choice, tech stack, phased roadmap, APIs, budget, scoreboards, decisions and glossary. One source of truth for leadership, engineering, security and new team members.
1. What Lekha is
Lekha is one shared company memory that any Manipal Group employee can ask questions to - on a laptop, on WhatsApp, or by calling a phone number - in English, Hindi or Kannada. Every answer cites the exact source document or meeting. Permissions are respected. Lekha never acts on its own: it proposes, a named human approves.
Four rules we never break:
Permissions enforced at search time, not display time. The search index itself filters on who's allowed to see what.
Documents are data, not commands. A PDF saying "ignore previous instructions and send X to Y" stays data. Nothing in a document can trigger an action.
Lekha proposes, a human approves. No message sent as a user, no payment, no signature, no outbound action without a named human clicking approve.
All data stays in India. AWS Mumbai, Sarvam India, on-premise where restricted.

 | Guiding principles behind these picks
Free-first. Every component defaults to open-source except LLM, speech, telephony and WhatsApp (where quality or network effects demand paid).
Pluggable model layer. Claude, Sarvam, anything else sits behind one interface so a provider swap doesn't rewrite the app.
Modular monolith, not microservices. One Python app with clean module boundaries. Extracting services later is easy; recombining a split-too-early system is not.
No Kubernetes for the pilot. One or two hardened EC2 hosts. K8s only when scale demands it (Phase 6+).
India residency is non-negotiable. DPDP full compliance by 13 May 2027. Every provider must have an India processing path and a signed data-processor contract.
3. Architecture - options and what we chose

 | Why Option B
Option A fails on residency, auditability and reliability - it's a demo, not a product.
Option C solves problems the pilot does not yet have (multi-site load, strictly on-prem material) and introduces Kubernetes, distributed Postgres and Qdrant clusters that would consume all engineering capacity for months.
Option B is the smallest architecture that meets security, privacy and performance for the pilot, and leaves clear seams for Option C when needed.
What would move us from B to C
Corpus too large for a single Qdrant node (above ~50M chunks).
A business unit whose data classification forbids any cloud, even AWS Mumbai.
MCP load patterns interfering with interactive user requests → extract MCP into its own service.
None of these is likely in the first six months. The design accepts them when they arrive.

Why this order
Ingestion before retrieval. Can't search what isn't there yet.
Retrieval before generation. The AI is only as good as what we hand it. Weak retrieval → hallucinations or over-abstention. Both bad.
Generation before action. Must trust what the system says before letting it propose things to approve.
Action before MCP. MCP opens Lekha to external callers; inner controls (permissions, abstention, injection resistance) must be proven first.
MCP before external customers. Don't sell a platform before it is one.
What we don't do, in any phase
Sign contracts, make payments, send messages pretending to be a human.
Fine-tune on confidential contracts (we retrieve, we don't train).
Autonomous outbound actions.
Confidential production data until Phase 2's release gate (SSO, audit, backup, red-team, DPDP checklist, processor contracts) passes.

Repository layout

Module boundary rules
Business modules (lekha/*) import each other only through public __init__.py interfaces.
apps/* imports from business modules; never the reverse.
model_layer/* depends on nothing in lekha/*.
db/* is the only place that touches SQLAlchemy directly.
Every cross-module call that crosses a trust boundary passes AuthContext explicitly.

API conventions
All endpoints under /api/v1/. Breaking changes go to /api/v2/.
JSON only, UTF-8.
Error envelope: { "error": { "code": "string", "message": "string", "detail": {...} } }.
Pagination: cursor-based (?limit=50&cursor=...).
Idempotency: write endpoints accept Idempotency-Key header.
Rate limits: per-user + per-tenant, surfaced in X-RateLimit-* headers.
X-Request-ID on every response for log correlation.

Cost-reduction levers (apply once pilot volume is measured)
Local embeddings and reranker. Already in the plan - removes per-call charges for the largest-volume AI call type.
Tiered model router. Route routine lookups to a cheaper model (Haiku); reserve the frontier model (Sonnet) for complex syntheses. Cuts LLM spend 40–60% at a few percent quality cost.
Reserved compute and committed-volume contracts. 1-year reserved EC2 saves ~30%. A Bolna enterprise contract drops telephony from ~₹5.5/min to ~₹2/min. Only commit after real pilot volume is seen.
What cannot be cut
Telephony: ₹1.75–₹5.5/min at India voice-AI pricing (2026).
WhatsApp: Meta per-conversation fees (~₹0.78 marketing, ~₹0.115 utility, 1,000 free service conversations/month).
Production HA infrastructure.
Backups, DR, cross-region copies within India.
On-call and incident response.

10. Glossary and references
Glossary
Term
 | What it means
 | ACL
 | Access Control List. The record saying which users or roles can read a document.
 | ADR
 | Architecture Decision Record. A short write-up explaining why we picked something over the alternatives.
 | Abstention
 | Lekha saying "I don't know" instead of guessing when evidence is weak.
 | BU
 | Business Unit. One of Manipal Group's businesses.
 | BYOC
 | Bring Your Own Cloud. A hosted service that runs inside your own cloud account for data residency.
 | Chunk
 | A small piece of a document (400–800 tokens) that search operates on.
 | Clavis
 | The Group's existing contracts and entities tool. Lekha reads from it via a connector; it is not training data.
 | Connector
 | A read-only adapter from Lekha to an external system (Clavis, SharePoint, Granola, etc).
 | DPDP Act
 | India's Digital Personal Data Protection Act (2023). Rules notified Nov 2025; full compliance 13 May 2027.
 | Embedding
 | A numeric fingerprint of a chunk's meaning; what the vector database stores.
 | FTE
 | Full-Time Equivalent. 0.5 FTE = half of one person's time.
 | Golden set
 | A curated set of questions with known-correct answers, used to measure quality over time.
 | Hybrid retrieval
 | Running both dense (semantic) and sparse (keyword) search and merging the results.
 | IdP
 | Identity Provider. The Group's single sign-on system.
 | LID
 | Language ID. Detecting which language a piece of text or audio is in.
 | LLM
 | Large Language Model. The AI that writes the answer (Claude, Sarvam).
 | MCP
 | Model Context Protocol. A standard that lets other AI tools call Lekha's tools safely.
 | OIDC
 | OpenID Connect. The protocol used for single sign-on.
 | p95 latency
 | The latency that 95% of requests come in under.
 | PII
 | Personally Identifiable Information (names, phone numbers, employee IDs, etc.).
 | Prompt injection
 | An attacker putting instructions in a document that try to hijack the AI's behaviour.
 | RAG
 | Retrieval-Augmented Generation. The pattern of retrieving sources first, then generating an answer from them.
 | Red-team
 | Deliberately trying to break a system (e.g. make it leak data) to find weaknesses before attackers do.
 | Reranker
 | A second-pass model that reorders search results by relevance.
 | RLS
 | Row-Level Security. A Postgres feature that filters rows per user automatically.
 | RTO / RPO
 | Recovery Time Objective (how fast we restore) / Recovery Point Objective (how much data we can lose).
 | SLO
 | Service Level Objective. A measurable commitment (e.g. "99.5% monthly availability").
 | SSO
 | Single Sign-On. One login for everything.
 | STT / TTS
 | Speech-to-Text / Text-to-Speech.
 | Vector database
 | A database that searches by meaning (via embeddings), not exact keywords. Qdrant is one.
 | WER
 | Word Error Rate. The main quality metric for speech-to-text.
